# ContextLattice v4.0.6: Identity With Receipts.

Agent memory is only durable when one logical event stays one event across every projection, and skill discovery is only useful when agents can prove which capability they used and whether it helped. v4.0.6 closes both loops.

The CLI remains the primary interface. The dashboard, HTTP, and MCP remain companion surfaces.

## What Changed

- Qdrant and pgvector projections now carry canonical event and content identity from the owner memory record.
- Retrieval reconciles vector results against owner authority, suppresses stale, missing, lifecycle-hidden, and duplicate path rows, and reports the exact reconciliation classes.
- Existing pgvector installations gain identity columns through an additive, nonblocking migration; no owner-memory rewrite is required.
- The native Skills Index scans configured Codex, Hermes, Hermes Ultra, and shared-agent roots while preserving per-root inventory.
- Byte-identical `SKILL.md` files collapse to one SHA-256 identity with every source path retained as provenance.
- Generic query words no longer dominate skill ranking; a deterministic discriminating-term coverage floor rejects weak matches.
- Skill usage advances through searched, selected, invoked, and independently verified-outcome receipts. Search alone earns no efficacy credit.
- Efficacy review produces bounded, inactive retain, note, revision, retirement, or abstention candidates; it does not edit, activate, or execute a skill.
- Agent-facing CLI and documentation surfaces now expose the receipt chain and the multi-harness Skills Index contract.

## Evidence Boundary

Deterministic holdouts cover current and stale projection identities, legacy duplicate paths, weak skill-query matches, exact-content duplicates, and cross-harness usage-to-outcome chains. The release proof binds those checks, the complete local suites, and the lane projections to an exact source tree.

The projection cleanup evidence records removal of one redundant pgvector secondary index while preserving the primary key and all owner data. That operator cleanup is not an implicit migration or permission to rewrite existing data.

## What Did Not Change

- Owner memory remains authoritative; vector stores remain derived retrieval projections.
- Public local mode remains account-free, and raw memory remains local by default.
- Skill search does not activate, edit, retire, or execute skills.
- Third-party skill improvements remain inactive local-overlay or upstream-PR candidates.
- Aggregate Signal remains a controlled activation preview under its existing privacy and utility gates.
- The public Apache-2.0 and commercial BUSL-1.1 source boundary remains unchanged.
- No Apple signing identity or notarization credential is bundled or implied.

## Upgrade

Existing v4 installations can update normally. No manual owner-data migration is required. On an existing pgvector deployment, the gateway adds missing projection identity columns without backfilling historical rows in the startup path; current owner-authoritative reads remain fail closed while projections converge.

Rollback is the prior immutable release tag plus its matching runtime payload. Preserve the active data volumes, rebuild only the affected ContextLattice services, and rerun health, index, and scoped retrieval proof after either upgrade or rollback.
