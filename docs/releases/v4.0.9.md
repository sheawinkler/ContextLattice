# ContextLattice v4.0.9: Recall With Proof. Cognition With Control.

Retrieval is useful only when an agent can tell what the evidence supports, what remains uncertain, and what action the evidence actually permits. v4.0.9 completes three increasing response-intelligence levels: governed learned context, proof-carrying recall responses, and Continuous Cognition over durable outcome evidence.

The CLI remains the primary interface. The dashboard, HTTP, and MCP remain companion surfaces.

## What Changed

- Learned context ranking is workspace-scoped and authority-gated. Candidate influence requires exact request scope, bounded selection receipts, eligible outcome evidence, and a fail-closed comparator; caller hints cannot widen the authenticated workspace.
- `recall_response.v1` turns one canonical context compilation into a bounded answer with support, opposition, temporal state, uncertainty, missing proof, progressive disclosure, and one advisory next action.
- Recall responses carry recomputable response and component identity. Quality samples, outcomes, Utility observations, independent verification, and impact evidence must retain that exact identity before downstream credit is available.
- Recall response CLI modes validate the returned contract and digest, make one authenticated request, refuse redirects, cap request and response bodies, and keep raw evidence and protected fields out of output.
- `continuous_cognition.v1` adds `observe`, `investigate`, `status`, `outcome`, `evaluate`, `rollback`, and `retire` over one fixed `as_of` boundary.
- Continuous Cognition projects canonical objective, session, proof, retrieval-plan, Utility, and one-shot preparation state. It performs no model call, provider call, runner execution, implicit context use, deletion, rollback, or retirement mutation.
- Outcome and evaluation projections require exact project, session, agent, task, task identity, workspace, response, lane, intent, sample, outcome, and Utility bindings. Future, conflicting, legacy-unbound, or cross-scope evidence remains unavailable.
- Causal eligibility is inherited only from the existing leakage-free exact matched-control projector. Contract validity never manufactures independently verified Utility or causal product lift.

## Evidence Boundary

The offline evaluator compared four conditions—no recall, retrieval only, static recall response, and Continuous Cognition—across five baseline and six disjoint holdout cases. Both response contracts passed the 11-case deterministic contract matrix with evidence precision `0.954545`, evidence recall `1.0`, citation/proof integrity `1.0`, and zero provider, network, or runtime-mutation calls. The fixtures are synthetic and prove contract behavior, not live model quality or independent Utility.

The merged private source passed all Go packages, Go vet, the complete race suite under the repository's official race-performance mode, the contract registry and boundary audits, the offline evaluator, Rust formatting and codec tests, host lifecycle audit, failure injection, installed-tool smoke, isolated scheduled-supervisor proof, and rebuilt OrbStack live route checks. The rebuilt gateway reported registry version 58 with all 168 context boundaries and all 142 native ownership entries present.

Exact public and public-paid release-tree audits passed from their committed projections. The strict paid audit's shared-proof storage threshold also reproduced its existing external-device timing sensitivity on the unchanged base; the repository's official shared-runner performance mode passed without changing the correctness or durability gate.

## What Did Not Change

- Owner memory remains authoritative; vector and learned indexes remain derived projections.
- Public local mode remains account-free. The new public routes do not add a hosted identity or mandatory cloud dependency.
- Recall responses and Continuous Cognition are advisory. They never authorize mutation or substitute for the runner, Git, filesystem, provider, or human/operator boundary.
- One-shot context preparation remains explicit and separately authorized. Cognition can report readiness but cannot recover a claim token, preparation identifier, artifact, or authorization digest.
- Raw prompts, completions, memory text, credentials, and protected preparation state remain outside the new response contracts.
- Aggregate Signal remains a controlled activation preview under its existing privacy and utility gates.
- The public Apache-2.0 and commercial BUSL-1.1 source boundary remains unchanged.

No memory, Utility, session, or task-store migration is required. Rollback remains tag-pinned: restore the prior gateway and tools, leave existing state in place, and stop invoking the new response routes. Existing owner records remain compatible and authoritative.
