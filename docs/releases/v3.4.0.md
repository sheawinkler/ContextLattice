# ContextLattice v3.4.0 - Agent Runtime Contract + Universal Adapter

Release date: 2026-06-05

This release upgrades ContextLattice from a memory service agents can call into a runtime contract agents can inhabit.

`v3.4.0` is the right public version boundary because it adds a new agent-facing product surface: sessions, objective state, adapter lifecycle commands, handoff metadata, and conformance checks across multiple agent runners. This is not a `v4` boundary because the external memory API stays compatible and the private tuning lane remains intentionally separate.

## What Changed

### 1) Universal agent adapter conformance

- Added the canonical `contextlattice-agent-adapter` CLI for bootstrap, context-pack, checkpoint, handoff, event, and completion flows.
- Added global installer wrappers, including `contextlattice_agent_adapter`, so agents can share one local command contract.
- Added adapter profiles for Codex, Claude Code, OpenCode, Hermes Agent, Pi, ChatGPT web/desktop, and Claude web/desktop usage patterns.
- Added `universal_agent_adapter_response.v1` validation so adapter responses are contract-shaped instead of best-effort text blobs.

### 2) Native agent runtime sessions

- ContextLattice now tracks live agent work as first-class sessions with typed events and runtime telemetry.
- Session APIs support start/list/read/event/complete flows through `/v1/agents/sessions` and `/telemetry/agents/runtime`.
- Agent Radar surfaces session and contribution telemetry for operators.
- `scripts/agent/contextlattice-session` supports runtime inspection and safe stale-audit cleanup.

### 3) Objective runtime contract

- Added `objective_runtime_state.v1` with required fields: `objective_state`, `action_executed`, `evidence`, `objective_delta`, `risk_or_blocker`, and `next_action`.
- Preflight, context-pack, and Dream Mode now return objective-runtime state when objective/session context exists.
- Auto-session helpers recover or start sessions when `CONTEXTLATTICE_SESSION_ID` is absent, unless explicitly disabled.

### 4) Agent templates and public contract docs

- Public agent templates now explain the universal adapter bootstrap/context-pack/checkpoint/handoff lifecycle.
- `llms.txt`, CLI docs, and public overview pages now name `v3.4.0` as the current public baseline.
- Public docs keep the private-v4 tuning lane separate from the stable v3.4 public contract.

### 5) Operational hygiene for audit sessions

- Added dry-run-first stale audit sweeping for objective-runtime audit/preflight sessions:

```bash
scripts/agent/contextlattice-session sweep-stale-audits --all-projects --pretty
scripts/agent/contextlattice-session sweep-stale-audits --all-projects --confirm --pretty
```

The command only matches known objective-runtime audit/preflight objectives with stale terminal audit events. It does not close arbitrary active agent sessions.

## Public Position

ContextLattice is the local-first memory spine under agent work: durable writes, scoped recall, skills discovery, CLI workflows, behavior provenance, typed graph edges, learning rerank, deep recall lanes, templates, and runtime policy behind one agent-facing contract.

The v3.4 public lane is now the stable place for builders who want agents that remember their work without each agent stack inventing memory badly.

## Version Boundary

- Public `v3.4`: stable public agent runtime contract and universal adapter surface.
- Private `v4`: tuning, experiments, and promotion candidates that still require benchmark, recall, and soak gates.
