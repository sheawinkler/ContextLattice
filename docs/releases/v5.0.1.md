# ContextLattice v5.0.1: Retrieval That Is Actually Ready

`v5.0.1` is the retrieval-readiness patch for the V5 authority model. A running process is no longer enough to declare retrieval healthy: the Gateway must prove its Qdrant collection, vector dimension, payload indexes, memory-store migration, and native source ownership before the runtime or its deployment healthcheck reports ready.

The CLI remains the primary interface. HTTP, MCP, the dashboard, and hosted endpoints remain companion surfaces.

## What Changed

- Gateway startup now owns one explicit Qdrant readiness contract. It creates a missing collection only when the startup policy allows it, verifies the natural FastEmbed dimension, preserves an existing compatible collection, and fails closed on a configured dimension mismatch.
- Startup and write-time collection creation share one single-flight authority. Rollback mode prevents every collection-create request, including conflict recovery.
- Qdrant payload indexes for `project` and `topic_tags` are required before `/readyz` becomes healthy.
- Compose healthchecks use `/readyz` instead of process-only health. A warming or blocked memory store therefore remains unavailable rather than being advertised as ready.
- The hosted/local smoke parses response JSON structurally and requires a non-degraded `ready` or `empty` result owned by the Go-native Qdrant adapter, with no Qdrant source error or dimension-probe fallback warning.
- Owner-only storage migration no longer depends on Linux `fchmodat2`. Descriptor-bound `openat` and `fchmod` enforcement retains inode, device, type, mode, and no-follow verification on Linux 6.1 hosts.

## Verification

The changed retrieval, readiness, smoke, and owner-only migration suites pass under the race detector. The migration regression also passes from a checksum-matched Linux ARM64 test binary on the affected Linux 6.1 kernel, including bounded idempotent migration and escaping-symlink rejection. Go vet, Go build, shell syntax, ShellCheck, public and paid lane guards, changed-tree leak checks, and the shared boundary/release-harness matrix pass.

The hosted paid boundary runs source-bound V5.0.1 code with the memory store ready, Qdrant indexes ready, a healthy Gateway and MCP adapter, restart counts of zero, and a non-degraded Go-native retrieval canary. The pre-repair Qdrant and memory-volume backup hashes remain valid, and Qdrant itself was not restarted during repair.

A paired payload benchmark over twelve alternating requests retained all 40 results while reducing mean serialized result bytes from 45,391.833 to 38,151.833, a 15.95% reduction. Its latency distribution did not improve, so this release makes no latency-gain claim.

The monolithic Gateway package exceeded its explicit 20-minute local ceiling without a changed-surface assertion. The release decision is therefore bound to the passing changed-surface race suites, build and static gates, prior V5 full-suite baseline, exact lane checks, and live runtime proof rather than presenting the monolithic timeout as a pass.

Hosted GitHub checks remain supplemental status; local deterministic evidence is the release authority.

## Upgrade and Rollback

Preserve Qdrant, memory, task, session, Passport, continuation, graph, and policy volumes. Rebuild and restart only the inventoried Gateway and MCP adapter from the exact V5.0.1 lane, then require `/readyz`, source-bound `/health`, and the structured retrieval canary to pass.

Rollback remains tag-pinned. Restore the prior Gateway and adapter images without deleting or recreating data volumes. A dimension mismatch, blocked owner-only migration, or unavailable payload index must remain fail-closed until its explicit cause is repaired.
