# ContextLattice v3.22.0

## Policy Laboratory

ContextLattice can now make retrieval and memory policy prove itself before it
earns production influence.

The CLI remains the primary interface. HTTP remains the integration fallback.

## What changed

- `contextlattice_policy_lab` exposes simulation, scoped policy cards,
  promotion recommendations, retirement, contradiction, storage-temperature,
  and governance status workflows.
- Same-snapshot simulation reports bounded token, latency, coverage, quality,
  source-selection, and sensitivity evidence without persisting or activating a
  candidate.
- Project, task-class, and retrieval-intent policy cards use sparse-data
  shrinkage, expiry, and explicit cross-project isolation.
- Promotion recommendations require assignment exposure, uncertainty bounds,
  drift cohorts, and survivor-bias checks before a candidate can advance.
- Memory retirement is proposal-first, non-destructive, legal-hold aware, and
  reversible through immutable apply/restore receipts.
- Contradictions now support weighted recommendations, abstention, operator
  decisions, reopen, and appeal while preserving both winning and losing proof.
- Storage temperature adds hot, warm, deep, and retired retrieval tiers with
  pressure-aware recommendations and explicit reversible movement receipts.
- The v3.21.0 release-pipeline regression is repaired: Context Pack boundary
  fixtures include complete retrieval proof and commercial route tests derive
  their expected route universe instead of hardcoding it.

## Product boundary

The public core includes deterministic simulation, advisory learning and
promotion, explicit non-destructive lifecycle operations, contradiction
workflows, and reversible retrieval-tier decisions. Operator and Enterprise
add entitlement-gated workspace history, scoped activation, canaries, review
queues, schedules, and bounded automation.

Paid automation remains explicitly bounded: it cannot install providers, issue
network calls, delete ordinary memory, override workspace identity, or activate
broad policy without explicit approval.

## Rollback

Deactivate the affected paid policy, stop due runs, and restore lifecycle or
storage mutations through their immutable receipt IDs. Public recommendations
remain advisory unless an operator explicitly applies them.
