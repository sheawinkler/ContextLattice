# ContextLattice v3.2.0

Release date: 2026-03-19

This release moves the public V3 runtime to a Go-first serving path for reads and gateway ingress.
Python is no longer the primary read/runtime lane; it remains available as fallback/rollback only.

## Included Runtime Cutover Commits

1. `7711608` feat(v4): default go gateway frontdoor on 8075 with parity routes
2. `3a0a7fc` feat(v4): route memory search through go staged retrieval by default
3. `1f29fb4` fix(v4): wire gateway-go memory-bank icm/fallback config and async lane defaults

## What Changed

### Primary Runtime Switch

- `:8075` now serves through `gateway-go` by default.
- Python orchestrator host port is moved to fallback lane (`:18075`).
- `/memory/search` executes in Go staged retrieval path by default (proxy fallback only on execution failure).

### Gateway Parity + Auth Hardening

- Added route parity for key orchestrator surfaces (`/health`, `/status`, `/memory/write`, task/telemetry/maintenance paths).
- Added bearer-token bridge to `X-Api-Key` in gateway proxy path to prevent auth-shape mismatch on proxied calls.
- Added codex preflight endpoint in Go gateway: `POST /v1/codex/preflight`.

### Memory-Bank Lane Reliability

- Gateway now receives the full memory-bank backend policy (`icm_spike` + configured fallbacks).
- `memory_bank` moved out of fast sync lane into slow async continuation lane to protect UX latency.
- Increased continuation inflight budget to avoid source starvation under concurrent slow-source warmups.

## Compatibility Notes

- Public endpoint guidance remains `http://127.0.0.1:8075`.
- Python fallback remains present for rollback safety; it is not the default runtime lane.
- This release keeps V3 product scope, while importing the Go-first runtime cutover improvements.
