# ContextLattice v3.20.2: One Source. Every Lane.

The release gate found two test files whose only difference was a deleted reference to private-development configuration. Runtime behavior was identical. Source identity was not. ContextLattice stopped the paid installer before a single asset escaped.

v3.20.2 removes that split without smuggling private development into paid builds. The same test source now understands that `premium_dev.env` exists only in the private development superset and is intentionally absent everywhere else.

The CLI remains the primary interface. HTTP remains the integration fallback.

## What changed

- Private and public-paid now execute one byte-identical commercial-truth and boundary-test source.
- The shared tests conditionally recognize the intentional absence of private-development configuration instead of deleting assertions per lane.
- The exact paid behavioral-source comparator now proves the tagged candidate against the approved private proof before compilation or packaging.
- `v3.20.1-public-paid` remains asset-free and is superseded by `v3.20.2-public-paid`.

## What did not change

- Utility Ledger recording, exact token accounting, outcome verification, analytics, advisory policy, durability, or rollback behavior.
- Private development remains a keyless superset; public-paid remains entitled and contains no private-development profile.
- Public core boundaries, quickstart requirements, third-party harness policy, and the CLI-first product contract.

## Verification

The patch must reproduce one source-identical private/paid test pair, pass both lane suites, regenerate the closed-world manifests, bind the exact private proof, and complete every installer job before assets publish.

## Rollback

Use public `v3.20.2` or paid `v3.20.2-public-paid`. Earlier paid patch tags intentionally carry no installer assets.
