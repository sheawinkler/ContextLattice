# ContextLattice v4.0.11: Recall That Arrives Ready

v4.0.11 promotes the retrieval and response-intelligence work from regression code into the current release. Agents receive source-bound context that clears the unchanged quality ruler, then a bounded response shaped for the actual job with enough proof to act intelligently without acquiring authority to execute.

The CLI remains the primary interface. HTTP, MCP, and the dashboard remain companion surfaces.

## What Changed

- Live context-pack scoring now distinguishes informational source notices from quality-impacting warnings. Every warning remains visible, but disabled-source and authoritative-current-state notices no longer reduce a quality score they do not invalidate.
- Current-state recall uses bounded topic and project indexes rather than project-wide replay. Corrupt selected indexes fail closed; proof-source revisions are captured atomically and compared without rescanning source history.
- The production recall route emits compositional responses by default when the proof and compact-budget contracts validate. Zero-percent component canaries label causal-attribution arms as control; they do not disable the response feature.
- A server-owned router derives task, object, temporal, provenance, and consequence facets and selects among ten bounded response modules.
- One proof spine binds the temporal premise, source snapshot, retrieval receipt, evidence, conflicts, gaps, component witnesses, and response identity with no second retrieval.
- Historical status, supersession, selective forgetting, negative recall, action preparation, explicit silence, portable identity, durable rollback anchors, and fail-closed v1 fallback remain preserved across native, script, Passport, and continuation surfaces.
- Dashboard dependencies retain the pinned Node 24.18/npm 11.16 contract and patch the affected `brace-expansion`, `minimatch`, and `nanoid` transitive versions.

## Promotion Evidence

The source-bound live retrieval benchmark uses the existing gateway `contextPackQualityScore` implementation without changing its threshold or weights. Across 60 held-out cases, serial and four-way concurrent runs both produced a mean of `99.783333`, median and p10 of `100`, minimum of `95`, and a `1.0` pass fraction against the existing `90` threshold. Serial context-pack latency measured 787.882 ms mean, 638.918 ms p50, and 1,620.498 ms p95. Four-way concurrent latency measured 3,610.251 ms mean, 3,628.109 ms p50, and 6,481.480 ms p95. The saved-recall path remained passing at 0.9 MRR and recall@5.

The untouched external compositional holdout contains 100 cases. Against the best qualified flat control, the product seam improved first-response resolution by 14 percentage points and downstream completion by 9 points. Tool selection and parameter binding each improved by 80 points on their ten-case subsets. All four paired comparisons pass Holm adjustment, median next-correct-action steps fall from 2 to 1, and the candidate remains within the fixed 16,000-byte and 4,000-token p95 envelope. All 149 reported failures are expected selected-module ablation rejections; unablated product, synthetic-control, unexpected-ablation, and promotion-blocking failure counts are zero.

Four closed provider-free transfer receipts cover the primary model and `gpt-5.6-luna`, each through native and script harnesses at max reasoning. The deterministic verifier passes all four receipts and records `observed_for_review`; it does not convert transfer observation into causal utility credit.

These are promotional product-seam and source-bound retrieval results. They do not claim live causal utility, provider cost, or production component attribution. Component canary allocations remain zero until signed operator governance is available and deliberately configured.
