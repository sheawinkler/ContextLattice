# ContextLattice v3.6.2

Release date: 2026-06-30

v3.6.2 is the current public release baseline for agent adoption. It packages the v3.6 operating-layer train and adds a prominent, agent-actionable quickstart so a human or an AI agent landing on the repo can install, verify, and integrate ContextLattice without a second prompt.

## Highlights

- Added `Agent Quickstart: Install + Integrate` directly under the README quickstart.
- Uses the explicit public repo URL: `https://github.com/sheawinkler/ContextLattice.git`.
- Gives agents a copy-ready install, health-check, integration, doctor, and failure-reporting path.
- Clarifies that `contextlattice_adopt integrate` writes managed instruction blocks for supported local profiles; it does not install Codex, Claude Code, OpenCode, Hermes, Hermes Ultra, Pi, Droid, or other third-party agents.
- Keeps the public v3.6 lane centered on durable memory writes, impact-per-token context allocation, agent discovery, CLI workflows, Skills Index discovery, runtime policy, template conformance, async recall steering, and local-first installer paths.
- Updates the Homebrew tap to resolve `contextlattice` to `3.6.2` for macOS users who opt into the first-party tap.

## Product Contract

The v3.6.2 docs update does not change the memory API. It makes the current adoption contract explicit:

- GitHub releases remain the canonical public installer surface.
- `gmake quickstart` remains the canonical repo-local startup path.
- The Homebrew cask is an optional macOS fast path.
- Agent integration is additive and managed-block based; existing user-authored instructions outside ContextLattice blocks must be preserved.
- Public docs should describe the public agent operating layer, not private Experimental tuning internals.
